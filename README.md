# 程序验证器（区间抽象解释）

实现一个小命令式语言的静态验证器，判断给定程序里的 assert 有没有可能失败或者发生除零，输出 SAFE 或 UNSAFE。

## 语言规格

只有整数变量，整数是任意精度的，没有溢出。程序是一条接一条的语句，每类语句如下：

- `input x in [lo,hi];` 声明一个输入变量 x，取值是 lo 到 hi 之间的任意整数，闭区间。lo、hi 是整数常量，可以是负数。输入变量是程序里唯一不确定的东西，验证器要覆盖它声明范围内的所有取值。
- `x = expr;` 赋值。
- `if (cond) { ... }` 或 `if (cond) { ... } else { ... }`。
- `while (cond) { ... }`。
- `assert(cond);` 断言，cond 为假就是失败。

表达式 `expr` 支持整数常量、变量、加减乘除 `+ - * /`、一元负号 `-`、括号。除法是整数除法，向零截断，C 那种语义：`7 / 2 = 3`，`-7 / 2 = -3`。**除数是 0 是运行时错误，和 assert 失败一样算不安全。**

条件 `cond` 支持 `== != < <= > >= && || !` 和括号。

一个程序示例：

```
input n in [0,10];
i = 0;
while (i < n) {
    i = i + 1;
}
assert(i == n);
```

## 判定语义

对每个程序输出一个判定：

- `SAFE`：输入变量在声明范围内取任何值，都不会有 assert 失败，也不会除零。
- `UNSAFE`：存在某个范围内的输入取值，会导致 assert 失败或除零。这时必须给出这个反例的输入赋值。

## 你要交付什么

写一个 `verify.py`，命令行入口：

```bash
python3 verify.py <程序文件>
```

读进程序文件，输出判定到标准输出，格式：

- 安全：一行 `SAFE`。
- 不安全：`UNSAFE` 后面跟空格分隔的 `名字=值`，覆盖程序里所有 input 变量，例如 `UNSAFE x=5 y=-3`。

反例必须是声明范围内的合法输入，而且要真的执行能触发 assert 失败或除零。全程本地，只许用标准库。

## 判分标准（`grade.py`）

```bash
python3 grade.py
```

`grade.py` 内置 31 个测试程序（15 个 SAFE，16 个 UNSAFE），覆盖这些翻车点：值越界、除零、循环 off-by-one、循环不变量被破坏、负数除法截断、布尔逻辑缝隙、大范围输入。对每个程序，判分脚本跑 `python3 verify.py <程序文件>`，检查：

- 判定和真值一致，SAFE 判成 UNSAFE 或者 UNSAFE 判成 SAFE 都不行。
- UNSAFE 的反例覆盖全部 input 变量、在声明范围内、并且真能触发（assert 失败或除零）。
- 单个程序限时 20 秒。

31 个程序全部通过输出 `PASS`，退出码 0；任何一个不过输出 `FAIL`，退出码非 0。

## 约束

- 全程本地离线，只许用标准库。
- 这是静态验证，不是穷举测试。有两个程序的输入范围很大（一个 10 万、一个 20 亿），穷举所有输入跑不动，必须用抽象解释：区间抽象加 widening 才能让 while 循环的不动点迭代终止，narrowing 才能把 widening 过近似掉的精度捡回来，否则 SAFE 的程序会被误判成 UNSAFE。循环迭代不终止和漏报是两个最常见的翻车点。
- 真值由判分脚本内置的解释器用穷举（小范围）算出来，反例用具体执行复核，你的验证器必须和它一致。
